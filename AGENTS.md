## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

## Project rules

- Public registration and contact submissions go through server functions (`src/lib/*.functions.ts`) using the admin client; anon has no table or storage write access — keeps applicant data and passport uploads server-validated.
- Registration validation lives in one shared zod module (`src/lib/registration-schema.ts`) used by both the form steps and the server — so client and server rules can never drift.
- Admin access = `admin` row in `public.user_roles`, granted automatically on signup only for emails listed in `public.admin_emails`; admin reads/updates rely on RLS via `has_role` — never check admin status client-side only.
- Passport photos live in the private `passports` bucket and are shown to admins only through short-lived signed URLs.
- Reference numbers (`MNL-YYYY-000123`) are generated by the database default on insert, never on the client.
- Public pages share the header/footer/bottom-nav chrome in `__root.tsx`; `/admin` and `/auth` render without it.
- Card payments use Paystack via server functions (`src/lib/payment.functions.ts`, helpers in `src/lib/paystack.server.ts`, the linked Paystack connector through the Lovable gateway); a registration is marked paid only after the server re-verifies the transaction with Paystack (callback page and `/api/public/paystack-webhook` both re-verify) — never trust the browser or webhook body.
- Money is stored in kobo (integers); fees live in `public.course_fees` (admin-editable) and the amount charged is always recomputed server-side from it.

- Registration numbers come from DB function `next_registration_reference()` (MNL-YYYY<batch>-000123), batch letter from `app_settings.current_batch` (admin-editable) — so batches change without code edits.
